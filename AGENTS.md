# Architecture decisions
- AI credit usage is recorded in a service-written/admin-readable ledger by both shared gateway helpers, observing terminal SSE usage without saving prompts; immutable login-account creator snapshots drive student attribution, live pricing snapshots give explicitly estimated credits, and missing usage stays NULL.
- Institution classes use students.archive_kind with an owner/name unique key and imported_lessons.archive_student_id; import triggers link future rows and course-protection triggers prohibit manual metadata or login changes while existing assessment modules remain reusable.
- Meeting-note imports: the extension stores the teacher's own credentials locally (user-chosen), signs in directly and calls the bearer-authenticated /api/meeting-plugin route (RLS as the teacher) for list/save; save keeps explicit confirmation, optimistic concurrency and refusal of ambiguous same-day sessions because ratings remain date-keyed; optional rating fields only overwrite filled values, a missing rating is created with in-app defaults, and progress items are appended. The /meeting-import nonce bridge remains for in-app imports.
- Online practice hints are pre-generated and stored on the question, served through existing authenticated question access and validated as method-only; opening hints never triggers AI or spends additional credits.
- Exam statistics identify whole-paper sessions by exact question-set coverage and derive correctness from saved attempt logs; sessions store validated pre-submission hint IDs, with NULL reserved for untracked historical usage.
- Bulk hint generation retains private batch provenance in math_question_hint_generation_batches; application users have no access, and only explicitly authorized maintenance tools may stage and apply validated hints.

- Online practice modes share a count selector with strict integer validation, retaining each server limit; exam practice subsets its loaded paper in the browser to preserve full-paper downloads and server behavior.

- Math knowledge tags use a self-referencing nullable `parent_id` with exactly two levels, preserving existing tags as top-level while allowing shared filtering across question-bank workflows.
- Calculation imports parse UTF-8 CSV explicitly without spreadsheet delimiter guessing, preserve Excel cell boundaries, split text pipes only outside TeX math, and reject extra columns or unpaired math markers before writes; this prevents formula fragments from becoming tags even through stale clients.
- Teacher homework and parent practice downloads share HomeworkBuilder so selection, ordering, screenshot preference and answer rendering stay consistent; parent data and image access must use authenticated student-scoped download functions with folder download permissions, while calculations retain the existing shared student access.
- Downloadable PDFs are prepared before a separate synchronous download action so browser downloads and mobile sharing retain user activation.
- Practice mistake analysis reads authenticated saved-session answers, streams through a server route, and atomically claims a durable account/day quota with session idempotency; this prevents forged results, duplicate billing and concurrent quota overruns.
- Explicit answer-correction batches update questions and append immutable old/new answer snapshots atomically to math_question_answer_change_log; teacher/admin-only reads and retained snapshots preserve traceability without write access.
- Explicit question-clarification batches atomically store old/new stems and answers in math_question_content_change_log; separate snapshots support unchanged answers while preserving the answer-only log contract.- Teacher accounts are created only by a server function that validates a teacher invite code (public sign-up is disabled) and records the inviter in teacher_invitations; this keeps the "every sign-up becomes teacher" trigger from being an open door.
- Student feature limits use students.access_level and are enforced server-side only when the caller is that student (hints revealed per question through a daily-claim RPC, stats refused, AI feedback limited to exam-paper sessions via a separate lifetime-claim RPC); the UI only mirrors the server decision.

- Non-streaming app AI calls go through src/lib/ai/astra-chat.server.ts (Responses API, streamed, chat-completions-shaped result) so all features share one default model and existing parsers.
- Extension credential-bearing messages require both the extension sender ID and the exact packaged popup URL, not absence of sender.tab; this admits legitimate popup pages while excluding website content scripts.
- Transcript extraction uses a self-contained injected module that walks the actual scrollable ancestor with overlapping samples, keeps timestamp-based utterance identity and returns traversal evidence; page-body fallback is prohibited — visible text is not proof of a complete transcript.
- Meeting session listing combines teacher-owned recurring, single and archive-linked imported lessons by selected date, keeping institution classes available to the same rating-backed import flow.
- Extension meeting polishing uses a bearer-authenticated teacher/admin-only public server route and the shared Responses stream helper; separate generated preview and retained local source prevent silent replacement, and durable gateway denial state prevents repeated blocked calls. Output language is a validated field appending only an output-language override to the unchanged diagnostic instructions. Optional class-note images (validated data URLs, limited count/size) are multimodal input alongside the transcript, with an appended note to verify transcript conditions against the images without inventing facts absent from both. Long transcripts (>= TRANSCRIPT_FILTER_MIN_LENGTH chars) are pre-filtered by low-cost google/gemini-3.1-flash-lite (src/lib/ai/transcript-filter.server.ts) to cut input cost; the filter preserves teacher wording verbatim, falls back to the original transcript on any failure, and surfaces only gateway 402/403 blocks.
